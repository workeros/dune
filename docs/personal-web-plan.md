# Dune 个人 Web 版本方案

日期：2026-09-05。状态：产品范围已确认；实际完成情况以当前代码和测试为准。

本文沉淀单机 MVP 后的下一阶段方案，作为个人 Web 版本的设计依据。本文中的目标能力不代表当前代码已经实现；单机基线见 [MVP](mvp.md) 和 [实现说明](implementation.md)，实际行为需结合当前代码和测试核验。

## 1. 目标与产品边界

Dune 面向个人研发用户，提供统一托管的 Web 站点，让用户接入自己的开发机，在浏览器中完成日常 Agent 编码工作。SSH 用于首次安装连接及必要的故障处理；日常使用通过 Dune 完成。

首版允许任何人注册、自由试用。成功标准是功能能够替代原来的 SSH 编码操作流程，不设置强制迁移人数、使用频率或留存率门槛。

Dune 是独立产品，不提供其他工具的兼容层，不接管外部已运行的对话或终端进程，也不导入其他产品的会话数据。

### 已确认范围

| 领域 | 首版决定 |
| --- | --- |
| 部署方式 | 运营方提供统一 Web 站点，用户接入自己的开发机 |
| 用户与权限 | 公开注册；每个账号只能访问自己绑定的机器 |
| 开发机系统 | Linux、macOS；不支持 Windows |
| 安装体验 | 尽量简单的一次 SSH 安装连接；退出 SSH 后 Dune 继续运行 |
| Agent 准备 | 安装 Dune 时不要求 Agent 已安装或登录 |
| Agent 接入 | 网页配置启动命令、参数和环境变量，选择 PTY 或 ACP；不绑定特定 Agent 品牌 |
| Web 功能 | 机器列表、项目目录选择、Agent 配置、多会话创建/继续/停止、PTY/ACP 交互、普通终端、只读 Git diff |
| PTY 生命周期 | 浏览器离线、Gateway 重启、Dune daemon 升级或重启不终止既有会话 |
| PTY 历史 | 默认最多保留最近 50,000 行，可配置；网页按需加载历史 |
| ACP 历史 | Dune 不保存对话消息；通过标准能力协商使用 `session/list` 和 `session/load` |
| 离线授权 | 保持等待用户确认，不因浏览器离线自动批准 |
| 数据位置 | 云端保存账号及机器绑定等必要信息；开发内容、PTY 历史和 Agent 原生历史留在开发机 |

首版不包含网页代码编辑器、复杂 Git 管理界面、团队共享权限、云开发机购买与创建、手机专项适配或外部运行会话接管。代码修改、测试与提交可通过 Agent 或普通终端完成。

## 2. 用户使用闭环

1. 用户注册并登录 Dune 站点，选择添加开发机。
2. 站点提供安装连接命令；用户在 Linux/macOS 开发机的 SSH 或本地终端执行。
3. 安装程序安装 Dune、绑定账号、启动后台服务。开发机主动连接云端，不要求用户开放开发机入站端口。
4. 用户在网页看到自己的在线开发机，选择项目目录。
5. 用户添加 Agent 启动配置并选择 PTY 或 ACP，也可先打开普通终端安装、登录或调试 Agent。
6. 用户创建会话、提交编码任务、处理授权、查看执行过程与代码 diff，并继续追问或停止任务。
7. 用户关闭网页后，远端任务继续；重新打开或刷新网页时只展示会话列表，用户点击会话后才连接并恢复当前交互状态及可用历史。断开连接保留远端进程，停止任务是独立操作。

Agent 配置可借鉴 [Zed Custom Agents](https://zed.dev/docs/ai/external-agents#custom-agents) 的 `command`、`args`、`env` 结构。具体配置格式需与现有 Profile 对齐，不把本文的字段描述当作已发布的新 API。

配置命令时无需以 Agent 预装成功作为保存条件；实际启动时返回命令不存在、权限不足、未登录或协议不兼容等真实错误。参数数组与 shell 命令应明确区分，不隐式改变用户命令语义。

## 3. 架构与数据责任

逻辑链路：浏览器 → Web 接入服务 → Gateway → 开发机 Dune → 会话宿主 / Agent。

开发机主动建立到 Gateway 的出站连接。Web 接入服务承担用户登录与浏览器协议适配；Gateway 按已经授权的机器标识路由。上述是逻辑职责划分，不要求首版全部拆成独立部署服务。

现有 Dune 底层执行能力继续保持可独立使用。账号、机器绑定和 Web 工作台属于本阶段增加的产品层，不把长期 Runner、Tenant、Fabric 管理模型一并纳入首版。

| 位置 | 保存或维护的内容 | 不保存的内容 |
| --- | --- | --- |
| 云端账号服务 | 账号、机器归属、机器凭证及撤销信息、必要机器元信息 | 项目文件、PTY 历史、ACP 对话、Agent API 密钥 |
| Gateway / Web 转发层 | 在线路由、认证上下文、必要且有界的传输状态 | 会话内容的持久副本，不在日志中记录会话正文或凭证 |
| 开发机 Dune | 机器身份、Agent 启动配置、项目与会话索引、PTY 当前画面和有界历史 | ACP 对话历史镜像 |
| 开发机 ACP 会话控制组件 | 能力协商结果、进行中的请求、待授权状态及恢复所需的最小索引 | 自行归档的 ACP 聊天记录 |
| Agent | Agent 自身配置、登录状态及其原生历史 | 由 Dune 代管的云端对话副本 |
| 浏览器 | 当前页面显示与交互所需的临时状态 | 作为唯一可信来源的会话状态 |

云端不保存会话内容，意味着开发机离线时，网页只能显示离线及云端已有机器信息，不能从云端读取终端或聊天历史。

### 账号与机器访问

公开注册必须与账号隔离同时交付。机器列表、会话查询、终端输入、目录读取和 Git diff 等所有入口都验证账号对目标机器的所有权，不能只靠前端过滤。

按当前部署要求采用 HTTP/WS、一次性机器绑定凭据和每机独立身份；浏览器登录凭据与机器连接凭据分开。提供解绑/撤销访问入口，撤销后已有连接不得继续授权访问。解绑不是删除开发机文件或终止 Agent 的隐式指令。

这些是支持已确认公开站点与机器隔离要求的实现约定。登录提供方、部署平台及具体凭证格式在实施时选定，不构成新的首版产品能力。

## 4. PTY 会话与历史

### 生命周期

PTY 会话不设置空闲超时自动退出。用户离开网页不会关闭 PTY，也不会停止继续读取输出。Gateway 或 Dune daemon 升级、重启后，应重新连接原会话，而非重新运行启动命令。

会话在用户明确停止、程序自行退出，或开发机/会话宿主失效时结束。开发机重启后不保证原进程继续运行；不能将终端历史恢复描述为进程恢复。

采用随 Dune 分发的私有 tmux 服务持有 PTY、进程、当前画面和历史。fabricd 使用 tmux CLI 管理会话，浏览器连接对应可丢弃的 attach 客户端；Runtime 元数据保存在 tmux session option 中。移除自研宿主和 VT 模拟器，不保留旧 server 兼容层，也不根据裸 PID 接管进程。
### 历史与显示

- 每个 PTY 会话默认最多保留最近 50,000 行历史，上限可配置；超过上限淘汰最旧历史。
- 当前终端画面及模式状态与滚动历史分开维护。TUI 的重绘、清屏、光标移动及 alternate screen 不能当作普通追加文本处理。
- 显式连接时由 tmux attach 恢复当前画面；进入或刷新页面仅列出会话，不自动 attach。
- 向上滚动或点击历史进入 tmux copy-mode，原生处理分页、实时输出及保留边界；不再建立另一套网页历史游标或 VT 状态。
- 默认 50,000 行是上限，tmux 会按原生批次淘汰最旧历史，实际保留行数可能低于上限。页面只传输当前可见终端，历史位于开发机 tmux 内存中。

程序自然退出后保留 pane 及历史，可从网页查看并删除。显式“结束并清除历史”销毁整个 tmux session；断开连接只退出 viewer。机器或 tmux server 退出不保证保留进程或历史。本阶段不加入终端录制、落盘恢复或旧 server 升级协议。

## 5. ACP 交互、历史与授权

### 标准能力协商

每条新 ACP 连接先执行 `initialize`，按 Agent 声明的能力决定可调用操作，不按 Agent 名称硬编码支持情况。

| 操作 | 产品行为 |
| --- | --- |
| 新建与对话 | 使用标准会话创建、prompt、update、取消及权限请求流程 |
| `session/list` | Agent 声明支持后调用，展示历史会话列表和元信息；按协议处理列表分页 |
| `session/load` | 仅在 `loadSession` 为 true 时调用，由 Agent 回放对话内容 |
| 不支持的操作 | 在界面明确报错并说明缺失能力，不伪造空列表或成功恢复，也不擅自改用 PTY |

`session/list` 与 `session/load` 是独立能力。前者用于发现历史会话，不等于获取完整对话；后者使用会话 ID、工作目录等参数恢复历史。加载期间接收 `session/update` 回放，等加载完成再发送新的 prompt。

Agent 通过标准接口列出其自身历史属于 ACP 能力使用，不代表 Dune 接管了其他产品已经运行的进程。

### 不保存消息的含义

Dune 不在云端或开发机另建 ACP 对话归档，不用自建消息日志补齐 Agent 缺失的历史能力。对话持久化由 Agent 自己负责。

开发机可以保存恢复所需的最小会话索引，例如 Agent 配置标识、`sessionId`、`cwd` 和必要会话初始化参数。不能假设所有 Agent 都支持 `session/list`，也不能把最小索引当作聊天历史。

网络传输、当前交互和待处理请求所必需的有界内存状态不属于历史归档。浏览器离线时，开发机侧仍需有存活的 ACP 客户端处理连接与进行中的请求；不能只让浏览器承担 ACP 客户端职责。

### 离线与授权

浏览器离线不会主动取消正在进行的 Agent 任务。遇到授权请求时保持等待；用户回来后展示仍有效的请求，确认后只向原请求应答一次。

如果 Agent 自行超时、退出或取消请求，展示实际结果，不把历史中已经失效的授权提示当作新的可审批请求。已发送但结果未知的输入和授权回复不得自动重放。

浏览器重连时需要协调实时执行与历史加载；标准能力未明确保证的并发 load 行为不能作为通用前提。该衔接在 ACP 适配实现与真实 Agent 验收中明确，不得为了补历史擅自停止正在执行的任务。

PTY 跨 daemon 重启的强保证不自动扩展为任意 ACP Agent 的原进程恢复。ACP 在运行进程中断后的历史恢复取决于 Agent 的能力与原生保存结果，错误在界面呈现。

协议依据：[Initialization](https://agentclientprotocol.com/protocol/v1/initialization)、[Session Setup](https://agentclientprotocol.com/protocol/v1/session-setup)、[Session List](https://agentclientprotocol.com/protocol/v1/session-list)。实施时按实际协议版本复核能力字段与请求参数。

## 6. 相对现有 MVP 的缺口

以下为本次只读代码核实结果，不替代实时测试。

| 领域 | 当前 MVP | 下一阶段新增工作 |
| --- | --- | --- |
| 接入方向 | fabricd 已主动连接 Gateway 并自动重连 | 安装绑定与公开站点接入 |
| Gateway | 单 daemon 路由、静态 target、共享 token | 多机器路由、账号隔离及机器身份 |
| 浏览器 | Go SDK / CLI 使用 WS + Yamux；现有入口拒绝带 Origin 的升级请求 | 浏览器可用的认证 API 与交互协议适配 |
| PTY 断线 | 订阅断开不停止 Agent，但无订阅时丢弃输出 | 当前画面、50,000 行历史、分页与重连衔接 |
| PTY daemon 重启 | guardian 清理旧进程；无重新接管机制 | 独立会话宿主、身份校验和重新连接 |
| ACP | JSON-RPC envelope 校验和透传，不解释会话及授权 | 标准 ACP 客户端、能力协商、list/load、等待授权 |
| Web 产品 | 未提供 | 工作台、机器/项目/配置/会话入口与只读 diff |
| 发布 | 手动构建与部署；完整验收主要为 macOS arm64 | Linux/macOS 发布安装及目标环境验证 |

## 7. 实施顺序

### M1：个人 Web 终端闭环

完成账号、机器绑定、机器列表、浏览器交互入口、项目目录与自定义启动配置。打通一台开发机上的普通终端和 PTY Agent。开发阶段可用单用户环境验证，公开入口必须经过账号隔离验收。

产出：用户从站点绑定机器、配置命令并在网页执行真实操作。

### M2：PTY 持久会话与历史

使用私有 tmux server，实现默认 50,000 行可配置历史、当前画面恢复、原生 copy-mode，以及 Gateway/fabricd 重启后重新连接。该阶段完成前不宣称具备可持续使用的 PTY 恢复能力。

产出：关闭网页、重启 Gateway 或升级 daemon 后，回到同一进程继续编码。

### M3：ACP 工作流

实现开发机侧 ACP 会话控制、能力协商、结构化对话、待授权处理、`session/list` 和 `session/load`。测试支持能力、不支持能力以及历史加载失败的明确界面行为。

产出：网页中创建 ACP 会话、执行真实编码、处理离线授权并按 Agent 能力恢复历史。

### M4：工作台与公开试用交付

完成多会话管理、只读 Git diff、Linux/macOS 安装与后台运行、升级流程、错误展示及使用说明。按下述标准完成真实任务验收后开放自由试用。

产出：可访问的统一站点、可安装的开发机版本及经验证的使用说明。安装的架构/发行版矩阵在发布时明确，不用单个平台验收结果代表所有 Linux/macOS 环境。

## 8. 验收标准

以功能替代和真实编码闭环作为验收，不以注册人数或使用率作为上线门槛。

| 场景 | 必须验证的结果 |
| --- | --- |
| 首次接入 | Linux/macOS 各验证安装、账号绑定、退出 SSH 后后台运行；Agent 未安装不阻塞 Dune 接入 |
| 账号隔离 | 两个账号绑定不同机器；通过修改请求中的机器/会话标识也不能跨账号查询、输入或读取 diff |
| 自定义 Agent | 可保存启动配置；命令不可用或协议错误时明确报错，并可通过普通终端修复 |
| PTY 真实编码 | 启动 Agent、输入需求、处理终端交互、运行测试、查看 Git diff、继续追问或停止 |
| PTY 网页离线 | 页面关闭期间进程继续输出；回来后恢复画面、可用历史和交互 |
| PTY 重启恢复 | Gateway 和连接 daemon 分别重启/升级后连接原会话，不重新执行启动命令，不重复提交输入 |
| PTY 有界历史 | 超过 50,000 行后仅淘汰最旧历史；配置上限有效；浏览器按需分页且实时画面不受历史回放污染 |
| ACP 能力边界 | 分别验证支持/不支持 list 与 load 的组合；不支持时报错，不把历史缺失当作空对话成功 |
| ACP 历史 | list 展示 Agent 历史会话，load 获取实际对话；Dune 没有持久化消息镜像 |
| ACP 离线授权 | 页面关闭后任务保持等待；回来可处理有效请求；超时或退出后的请求不允许重复审批 |
| 数据位置 | 云端持久数据和日志不包含会话正文、PTY 历史或 Agent 密钥；机器离线不伪装成历史可读取 |
| 真实 Agent | 使用实际可运行的 PTY 和 ACP Agent 完成代表性编码任务；mock 验证不替代真实业务验收 |

各实现阶段按实际变更完成相应自动化与真实环境验证，再更新验收记录。
