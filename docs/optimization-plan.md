# Dune 优化执行方案

评审基线：main / cd9513a。整理日期：2026-09-17。

状态：代码实现、SandDance 消费者同步及本地集成验收已完成。实施方法按 SOLID/KISS 收紧，SandDance 已 rebase 到 origin/dev。实现事实、版本和最终验证证据见 [优化交付记录](optimization-delivery.md)；真实 Agent、休眠和完整目标平台现场验收仍按该记录列为未验证，本文验收矩阵不等于均已实际执行。

## 1. 目标与范围

本轮处理现有能力的正确性、职责边界、性能和流程闭环。新增能力限定为已经确认的路径与内容搜索，以及 SandDance 现有文件界面的搜索交互。

| 组件 | 本轮职责 |
| --- | --- |
| Dune 个人前端 | 个人工作台、Attached 接入、可选的个人 Managed 环境、PTY、ACP 和现有工作台操作 |
| 宿主与 SandDance | 企业租户界面、角色规则、资源供应与生命周期编排；在现有文件界面交付搜索与定位 |
| Dune Host / SDK / API | 提供通用能力、权威身份与资源事实，执行宿主策略，保持操作合同一致 |
| Gateway | 承担网络路由、授权执行和连接边界；peer owner 保留独立校验 |
| fabricd | 执行、Runtime 生命周期、文件、Git、搜索和端口能力 |

不扩展账号恢复、IM 审批、额外 ACP 协议能力、全局搜索替换、多根工作区、持久搜索索引或 Dune 内置完整文件编辑器。Managed 供应商编排、数据库恢复和跨连接透明迁移继续属于既有边界之外。

遵循原型阶段约定：直接更新 API、类型、配置及调用方，删除失效实现，不引入兼容别名、旧接口适配层或迁移垫片。SandDance 的真实消费者必须同步更新依赖、代码、测试和文档。

实现遵循以下 SOLID/KISS 约束：

- 按现有模块职责修改：authorization 组织身份/资源事实和宿主策略，access 执行流授权，Gateway 负责传输，fabricd 负责执行。只有真实的职责或生命周期边界才增加类型和模块。
- 使用现有 identity.Service、access.Checker、managed.Service 等宿主扩展点。具体操作和私有辅助函数直接实现，不为未来可能的第二种后端预建 Provider、Factory 或注册表。
- 每份可变状态有明确的唯一负责方；其他层读取或调用它，不维护同一职责的缓存、定时器和状态副本。
- 接口只暴露消费者实际需要的能力。凭据期限放在认证结果，搜索选项放在独立的请求类型，不把 User、File 或 Host.Options 扩成万能容器。
- 模块之间依赖现有的窄接口；单个模块内部优先具体类型和普通函数，不为测试替身给每个函数再包一层接口。测试验证合同、竞争与失败恢复行为。

## 2. 已确认的核心决策

| 主题 | 确认后的合同 |
| --- | --- |
| 内置前端 | 聚焦个人；企业租户界面由宿主承担；保留可选的个人 Managed 能力 |
| 解绑授权 | 普通用户解绑统一为宿主 runner.unbind 策略，个人默认 owner；Dune 提供事实并执行约束与事务 |
| 鉴权缓存 | 既有交互流最多增加 5 秒撤销发现延迟；新操作实时鉴权；凭据自然到期不能被延长 |
| 文件写入 | 同 Engine 的 Files/Upload 条件写串行；外部修改尽力检测；明确 create、conditional、unconditional 三种意图 |
| 文件修订号 | 由内容与权限位决定；仅 mtime 改变不冲突；编辑读取校验完整原始字节；覆盖保留权限位 |
| PTY 超时 | fabricd 离线仍生效，计入主机休眠；TERM 后最多 2 秒再 KILL；保留历史并记录 timed_out |
| 搜索 | ripgrep 支持路径/内容两种模式；单次有预算查询；显式返回不完整原因；不做持久搜索分页 |
| 搜索界面 | Dune 提供 API/SDK；SandDance 现有文件界面接入筛选、结果和定位；只搜索磁盘内容 |
| 已有配置接入 | 直接报错，不消费新令牌，不改变原绑定 |
| 安装恢复 | 有有效配置则修复本地安装；无有效凭据且结果未知则准确核对、撤销原接入后重新生成命令 |
| 升级 | 独立动作、保留绑定和 SessionDir；新版完成本地启动检查后清理旧程序，不保留回退版本 |

设计决策树已收敛为以下交付分支：产品边界、授权、文件一致性、PTY 生命周期、搜索、安装升级、性能与验证。剩余工作是实现与验证，不需要重新选择已经确认的产品范围。

## 4. 目标设计

### 4.1 授权与撤销窗口

沿现有 authorization.Service 的解绑用例补齐事实与策略调用，复用当前资源查询和撤销事务；不再增加一个同职责的应用服务层。

普通用户解绑的执行顺序：认证用户 → 读取权威 owner、creator 和完整 binding → 宿主 runner.unbind 策略 → 校验策略期限及原 binding → 原子撤销。creator 只表达数据库实际保存的身份标识，不构造数据库不存在的身份字段。宿主保留角色与创建者规则，Dune 不引入企业角色模型。

删除 CanDetachAttached 重复回调。SandDance 的 can_detach 展示与实际解绑共享宿主规则，避免再次分叉。待接入 enrollment 的取消仍保持 pending-only 语义；受信宿主的 Managed Revoke / SetSuspended 也保留独立边界，不转成用户 cookie 解绑接口。

5 秒窗口的起点是权威接口已经能够返回失效的时刻，终点是 Gateway 不再放行后续消息。它不承诺回滚已受理操作、停止已经启动的 Agent，或使已转发的排队输入立刻消失。fabricd 仍使用独立的输入租约和执行 fencing。

- 对每个新的协议 request 实时验证身份、Runner 和操作策略；已有交互流首次出现新的 action 也实时验证。
- 同一 action 的连续交互输入/输出可复用有界允许事实。作用域固定在原身份、目标、binding 和 action，不能扩展成整连接任意操作许可。
- 允许事实同时受身份期限、Runner 状态、操作策略和 5 秒总上限约束。现有 AccessChecker 的 30 秒交互租约必须同步收紧。
- 时间从权威调用开始前计算；慢回复消耗预算。Web、Gateway 和 peer 不能通过转发或重复使用旧结果重新续期。
- 明确拒绝、刷新失败或期限到达后停止放行；迟到响应不能复活已关闭授权。空闲流也要按期限关闭。
- Authenticate 返回单独的认证结果（例如 AuthenticatedSession，包含 User 与 ExpiresAt），更新本地实现和 SandDance 适配器；不把凭据期限塞进持久用户身份，也不为缓存增加 Refresh/Subscribe 接口。离线 JWT 验签无法发现的上游注销不属于可观察撤销。
- peer owner 沿用现有上下文独立查询权威接口，维护自己流内的许可；保留现有 peer 身份、nonce 和请求摘要验证，不增加可转发的授权证据或跨副本缓存同步。target、incarnation/generation、route、epoch、Runtime 和 input grant 继续逐次检查。
- 托管 ACP 的每次 prompt / permission / cancel 是新操作；原始 ACP 正文不解析，只能承诺原始流的授权窗口，不能宣称其中每个 JSON-RPC 都单独实时鉴权。

持续用户流复用 pkg/access 中现有 checkedStream.leases/watch 作为唯一许可缓存与刷新器。authorization 按固定 ConnectionAccess 组合一次实时检查：身份 → Runner → 宿主策略，返回不晚于“调用开始 + 5 秒、凭据期限、策略期限”的决定；access 只处理决定与期限，不依赖 SQL 或企业身份实现。新 request/action 走实时检查，连续消息查现有流许可。收掉同一路径中 Web 每帧重查和重复的用户连接刷新职责；保留 Web 准入校验及无用户策略的机器连接自身校验，不另建全局 Session 缓存或连接缓存。

SandDance Managed 状态中的“访问已关闭”应准确区分持久门禁已经撤销与各 Gateway 的传播截止时间；没有全副本确认就不报告所有 Gateway 已当场关闭。禁用一个用户只失效该身份的流，不能通过 target 级断连影响同一环境的其他用户。

### 4.2 文件读取、修订号与写入

普通列表、搜索和 metadata-only stat/preview 不生成伪修订号。需要编辑或冲突检查的调用显式请求内容摘要与有效 revision；目录不提供文件内容 revision。SandDance 的周期冲突检查、覆盖上传和编辑读取同步适配。

读取字节、内容摘要和权限来自同一个打开的文件描述符，避免读取对象与按路径重新打开的摘要对象不一致。分块读取仍不构成快照；客户端进入可编辑状态前必须校验完整 EOF、原始字节长度及 SHA-256。摘要不一致即本次读取失败。预览发生本地截断时保持只读，即使远端最后一块报告 EOF 也不能把部分内容当作完整文件。

Files write 与 Upload create 共用三种互斥意图：

| 意图 | 行为 |
| --- | --- |
| create | 目标已存在就失败，使用原子的 no-clobber 提交，不采用先检查再 rename |
| conditional | 必须提供 revision；在提交锁内验证当前内容和权限，匹配才替换；字段缺失不能降为无条件写入 |
| unconditional | 显式跳过 revision 比较，其余目标类型、权限和写入约束继续执行 |

Upload 创建时固定意图和 expected revision，commit 不允许临时改写。冲突不得修改目标；结果未知不能自动转为 unconditional 重试。

保留一个 Engine 内统一的文件写入锁，覆盖目标检查到提交替换。只读操作、上传传输及临时文件内容准备移出该锁。rename/remove 与 upload commit 继续使用同一协调机制。大目标的条件摘要仍会占用写锁，这是本轮为了清晰串行语义保留的性能成本；暂不引入路径锁体系或文件快照服务。

覆盖时保留当前目标的权限位，在临时文件提交前完成 chmod 和必要同步。新建采用明确的默认权限。返回值描述本次提交的已知字节、摘要和最终权限，不能提交后重新打开路径而返回外部后续修改的 revision。权限保证不延伸到 owner、ACL、xattr 或 inode 身份。非普通文件目标应明确拒绝不支持的替换，不能一边跟随 symlink 生成 revision、一边用 rename 替换链接本身。

此锁不协调 Git、Shell、Agent 或本机编辑器。对这些修改保留已确认的尽力检测边界，不宣称持有 fd 或内容摘要消除了比较与替换之间的外部竞争。

### 4.3 PTY 超时与历史

期限从命令启动开始计算，不把 start timeout 改成整个 Profile setup 的总超时。实际经过时间包含 fabricd 离线和主机休眠；休眠期间无法执行终止，唤醒后立即处理。运行中使用能够表达包含休眠的经过时间的时钟，避免手动调整日历时间无限延长期限。

复用现有 RunHelper 分派，为有超时的 PTY 增加一个私有 helper，每个此类 Runtime 对应一个守护；不引入另一项常驻服务或通用 supervisor 接口。守护在 Runtime 创建时已经运行，直接持有并终止受管进程/进程组，不依赖 fabricd 的内存计时器或存活管道；到期也不再执行旧 release 目录中的 dune/tmux 程序。

到期发送 TERM，最多等待 2 秒后发送 KILL。停止的是 pane 中的工作，tmux dead pane 与历史保留。Runtime 的终态使用明确的 timed_out 原因；停止原因和期限信息可由新 fabricd 恢复读取。自然退出、超时、显式 runtime stop 相互区分；显式 stop 仍销毁 session 和历史。

helper 是自身期限和进程终止原因的唯一写入者，fabricd 只恢复读取。需要恢复的字段保存在 SessionDir 内按 Runtime ID/incarnation 关联的小记录中，清理随 session/history 生命周期执行；tmux 继续负责 pane 和历史。不复制整份 Runtime 元数据，不建立第二套 Runtime 数据库，也不靠一个特殊退出码猜测是否超时。

不保证主动脱离受管进程组的进程被清理，也不增加机器重启后的进程/历史恢复。tmux 或主机退出仍受现有生命周期边界约束。

### 4.4 ripgrep 搜索

沿现有 files/search 入口使用独立的 SearchOptions/SearchResult 类型，区分 path 与 content 模式；搜索参数集中在 search 字段，不继续给通用 File 请求平铺搜索开关。响应与目录分页分离。实现使用具体的 rg 调用函数，不另建 SearchProvider 接口或持久搜索会话。

| 能力 | 首版行为 |
| --- | --- |
| 路径搜索 | 相对路径字面子串匹配，保留现有默认不区分大小写的语义；只返回文件 |
| 内容搜索 | 字面文本或 ripgrep 默认正则，支持大小写和全词开关；不启用跨行或额外高级正则引擎 |
| 文件过滤 | 相对 root 的 include/exclude glob；两种模式共享候选范围规则 |
| 默认范围 | 单个指定目录，遵守 ignore，包含隐藏文件，排除 .git 内部数据，不跟随目录符号链接 |
| 参数调整 | 允许调整隐藏文件和 ignore 规则；参数不能隐式改变 root |
| 内容编码 | UTF-8 文本及 UTF-8 BOM；其他编码明确跳过，关闭自动转码 |
| 返回 | 文件路径、命中行、范围和上下文，以及是否完整和不完整原因 |
| 一致性 | 磁盘扫描时观察到的结果，不是快照；未保存草稿不参与工作区搜索 |

include 只缩小候选范围，exclude 与 .git 排除优先。不能直接把多个 rg -g 参数拼起来，因为 include glob 可覆盖 ignore。rg 负责遍历及 ignore/隐藏/链接规则；Dune 只用小的共享函数校验路径和应用 include/exclude，glob 使用现成匹配器，不重写 gitignore 引擎。候选路径流式消费，内容模式按有界批次交给 rg，不缓存完整文件树；两种模式共用这些函数即可，不建立搜索执行框架。

发行包固定 rg 版本，覆盖 Linux/macOS 的 amd64/arm64，带校验信息和许可证。服务使用随包程序，不依赖目标机偶然存在的 PATH 版本。用结构化 argv 调用，禁用 rg 用户配置；文件枚举用 NUL 分隔，内容结果用 JSON，根路径和查询不能拼进 shell。

UTF-8-only 需要实际验证文件字节，不能仅凭 rg --encoding 或某条 JSON 的 text 字段判断。rg 先产生候选命中，仅对有命中的文件做一次有界读取，UTF-8 验证、命中范围和上下文核对共用这些字节；文件已变化则舍弃该文件结果并注明原因。验证计入查询预算；未完成验证的命中不能返回成确认结果。不做前置全目录编码扫描，不为统计未命中文件的编码而额外读取，也不建立编码缓存或快照。非 UTF-8 文件名无法由现有 JSON 字符串协议无损回传，应跳过并注明原因；有效 UTF-8 名称中的换行或 tab 要正确解析和显示。

所有查询限制时间、结果数量、响应字节和子进程并发；内容模式另限制文件大小、单条 rg 记录、匹配范围和上下文，路径模式不因文件内容大小排除结果。初始工程预算可采用：默认 200 / 最多 1000 个命中，结果序列化不超过 1 MiB，默认 5 秒 / 最多 10 秒，每个 Engine 同时运行 2 个查询、每个 rg 最多 2 个工作线程；内容模式单文件最多 16 MiB、单条 rg 记录最多 256 KiB。预算在实现基准中校准，但不得退回无限扫描或隐藏截断。

这些上限先用模块内常量、每查询计数器、一个 context deadline 和 Engine 级 semaphore 实现；请求只提供调用方实际需要的 limit/timeout 等参数。校准常量不要求动态配置、租户预算策略或通用资源调度器。

忽略规则排除属于正常搜索范围；耗尽预算、编码不支持、部分目录不可读等必须分原因报告。合法 root 内的部分失败可以返回其余结果；root 无效或不可访问则直接失败。单条超长行及大量 submatches 也受预算约束，不能先读入无限长 JSON 再检查大小。

取消沿浏览器 AbortSignal → HTTP context → SDK stream → Gateway 转发 → fabricd 请求级 context → rg 终止和 Wait 贯通。新搜索、切换 root 和关闭界面取消旧查询，并拒绝迟到结果。取消改动限定只读搜索，不改变已受理写入或 Agent 请求的断线语义。

SandDance 搜索结果按文件展示，并转换 rg 字节偏移为编辑器使用的位置单位。点击结果后，核对实际加载内容与命中文本/上下文；已变化时提示重新搜索，不能只按旧行号跳转。已有 dirty tab 保留草稿并提示磁盘结果；clean tab 也需要检查是否过时。命中超出编辑器已加载范围时明确提示，不报告虚假的定位成功。

### 4.5 目录浏览

目录列表独立保留，继续支持空目录和目录选择。内置前端停止调用带 4096 项硬上限的旧 list，统一到目录分页；SandDance 也停止自动循环拉尽所有页，改为首屏加载和按需加载更多。

首版固定名称排序：服务端按批读取名字，用标准库 max-heap 保留 pageSize+1 个候选，最后排序并读取当前页元数据。游标只携带目录和最后名字，不增加可配置排序、签名服务或通用分页器，也不承诺跨页快照。为了避免引入结果集状态，每页仍可能扫描完整目录；本轮改善内存与 UI 首屏工作量，不承诺扫描时间与目录大小无关。

如果预算内未完成有序页所需的扫描，明确返回扫描未完成错误，不能把未完成扫描的候选伪装成完整有序页。目录变化仍可能造成跨页遗漏或重复，应允许重新加载。

### 4.6 接入、恢复与升级

统一个人和宿主生成的安装实现，保留各自签发接入命令的权限边界。接入与升级使用明确的不同动作。

接入开始时只要目标配置已存在就报错，不消费新令牌、不隐式升级或重绑。配置损坏也不能当作不存在。默认不增加多账号并行安装；不能只更换配置文件名却复用 SessionDir 和服务名。

生成个人命令时即提供稳定 Runner/接入标识，复用待接入结构，使失败恢复能够定位准确对象。配置采用原子且不覆盖已有目标的写入；凭据只在必要位置保存。

| 失败状态 | 恢复动作 |
| --- | --- |
| 下载/解压或 enrollment 提交前失败 | 令牌仍有效时可重试原命令 |
| 绑定可能已经提交，但本地没有有效凭据 | 显示准确接入标识和结果未知；核对并撤销原接入后生成新命令；不重放 enrollment 或尝试取回凭据 |
| 配置完整，但程序/服务安装失败 | 使用原配置补完本地安装，不再 enrollment |
| 配置完整但云端凭据已撤销 | 明确报告绑定不可用；升级不隐式重绑 |
| 取消或解绑返回结果未知 | 先读取准确状态，再决定后续操作 |

升级流程：完整下载并校验新程序包 → 准备新程序目录 → 停止并排空旧 fabricd → 更新服务执行路径 → 启动新版并确认本地初始化完成 → 删除旧程序目录和本次临时文件。

就绪证明限定为本次启动：新版成功完成配置/TLS 检查及 fabricd.Open（状态锁、tmux 恢复、必要 helper 初始化）后，写入一个私有启动回执，包含本次启动 nonce、进程身份和实际程序目录。安装器确认回执匹配且目标进程仍在运行后清理旧目录。它不是持续健康承诺；无需模拟 Agent 请求、公开健康 API、常驻监控或版本注册表。systemd/launchd 接受启动请求本身不能替代该回执；Gateway 连接状态单独展示。

只有安装器拥有的程序目录属于清理范围，配置、证书、SessionDir、tmux socket、Runtime 记录和工作目录都放在持久位置并保留。不建立 previous 链接或旧版本归档。成功切换后清理旧程序；未成功切换则明确报告失败，由修复流程继续，不承诺自动回退。

服务定义、PATH 和后续 helper 调用不能继续指向已删目录。清理旧文件不包含杀死仍承载 PTY 的 tmux/超时守护；已运行映像占用的磁盘空间可在其自然退出后释放。本轮保持已固定 tmux 版本，新客户端必须能访问已有私有 server，不顺带升级或重启承载会话的 tmux server。

## 5. 边界收敛与其余性能工作

- 移除内置 Tenant 列表、选择、创建及企业专属凭据表单假设。个人 Managed scope 明确取当前用户，保留模板、创建、状态、暂停/恢复能力判断和删除流程。
- 删除 machine HTTP 兼容路由和仅为这些路由存在的包装，执行入口统一使用完整 Runner binding。保留协议 machine target、connector 凭据、enrollment machine 身份与 binding.machine_id。
- 删除没有 Dune/SandDance 消费者的 pkg/renewal。保留有真实宿主消费者的 pkg/fabric、Managed 状态和宿主续期任务。
- 登录限流按受信代理配置解析来源；不信任任意客户端提供的转发头。使用来源和账号等适合登录的限制维度，避免所有 Nginx 用户共享一个额度；保持简单的现有部署范围，不引入分布式限流服务。
- Git 同一仓库仍协调执行，不同仓库允许并行。锁键根据规范化 Git common directory 识别，覆盖路径别名和共享 refs 的 worktree；用私有按键锁辅助函数，只保留正在使用或等待的条目，不增加跨操作调度系统。
- ACP 先用单个 reducer 维护现有有界条目数组、每项大小和总大小，仅重新计算发生变化的条目；保留直观的查找，只有性能分析证明需要时再增加索引。浏览器仅在开启调试视图时保留调试条目，不为此增加第二套状态仓库或扩展 ACP 协议；必要时合并渲染。
- Web 按实际使用拆分终端、ACP 等重依赖，检查入口包和交互耗时，不用压缩文件大小替代真实可用性验证。

## 6. 交付拆分与依赖

每个交付项都包含调用方更新、文档和相应回归；不将所有风险合入一次重构。

| 顺序 | 交付项 | 完成标准 |
| --- | --- | --- |
| 1 | 解绑授权收敛、权威 creator 事实、SandDance 策略更新 | 所有保留入口一致拒绝未授权解绑，pending 取消与 Managed 生命周期不混用 |
| 2 | 文件修订号、三种写入意图、完整编辑读取 | 复现的静默覆盖被阻止，权限保持正确，混合分块内容不能进入可编辑状态 |
| 3 | 独立 PTY 超时守护与终态 | fabricd 离线、恢复及主机休眠场景符合期限与历史合同 |
| 4 | 个人前端/宿主边界、废弃 HTTP 与孤立包清理 | 个人与 Managed 现有流程可用；没有失效入口和兼容分支 |
| 5 | 身份期限接口与 5 秒流授权 | 新操作实时，持续流总窗口有证据，跨 Gateway/peer 不叠加 TTL |
| 6 | rg 搜索 API、发行依赖及 SandDance UI | 路径与内容搜索选项、取消、不完整反馈和定位闭环；磁盘/草稿边界明确 |
| 7 | 安装恢复、独立升级、旧程序清理 | 首装/失败修复/升级可区分，成功切换后旧目录删除且保留中的 PTY 正常 |
| 8 | 目录、Git、ACP、限流与入口包优化 | 内存/查询/锁竞争有针对性改善，并记录尚保留的扫描或串行成本 |
| 9 | 集成验收与文档收口 | Dune 与 SandDance 针对最终依赖版本完成验收，平台未验证项明确记录 |

PTY 守护、rg 打包与升级清理必须在最终发行验收中汇合。文件修订号与搜索定位共享读取方的正确性要求。授权接口变更与 SandDance 的依赖切换应作为同一交付边界，不能只在邻接目录临时替换依赖后宣称集成完成。

## 7. 验收矩阵

| 类别 | 必须覆盖的场景 |
| --- | --- |
| 解绑 | owner/admin/creator/普通成员；所有保留用户入口；旧 binding；宿主拒绝、超时；pending 取消不能撤销已绑定 Runner |
| 授权窗口 | 活跃/空闲流、慢权威调用、策略撤销、自然到期、刷新错误、迟到结果、peer 转发；5 秒从可观察失效到 Gateway 停止转发测量 |
| 执行边界 | 新 action 实时鉴权；原始 ACP 合同明确；input grant/epoch/Runtime 过期继续拒绝；用户禁用不误伤其他身份 |
| 文件 | 等长保留 mtime 修改、权限变化、mtime-only、同引擎并发条件写、混合分块、预览本地截断、覆盖上传、非普通目标、提交响应对应本次字节 |
| PTY | 超时前后重启 fabricd；fabricd 停止期间到期；TERM 不退出后 KILL；自然退出与 timed_out 区分；恢复历史；休眠计时 |
| 搜索 | 两种模式、中文/emoji 位置、case/word/regex、glob 与 ignore 优先级、隐藏文件、无跟随链接、UTF-8/BOM/非法编码、换行文件名、超长行、无命中与部分失败 |
| 搜索预算 | 时间/数量/字节/文件大小/并发触顶，取消会回收 rg，无迟到 UI 结果；保留的结果和不完整原因一致 |
| 搜索定位 | dirty tab 不丢草稿；clean tab 或磁盘变化不错误定位；编辑器未加载区域明确提示 |
| 安装 | 已有有效/损坏配置均报错；令牌未消费；提交后响应丢失；配置落盘失败；服务安装失败后使用原配置修复 |
| 升级清理 | 新版本地初始化完成后旧目录删除；服务和 helper 使用新路径；配置/SessionDir 不变；离线状态与启动失败分开 |
| 组合生命周期 | 启动带 timeout PTY → 升级并删除旧程序 → 停止 fabricd → 到期结束 → 启动新 fabricd 后读取历史和 timed_out；同时能新建 PTY、执行命令和启动 ACP |
| 性能 | 流输出不再按每帧进行重复权威查询；大目录不一次堆积全部结果；不同 Git 仓库不互相阻塞；ACP 内存有界且避免全量重算；记录 Web 包和交互基线 |

实现时按改动选择针对性回归，再执行 Dune 主模块、IM 模块、Go 静态检查、Web 类型检查与构建，并在接口/前端交付项验证 SandDance。授权与绑定 SQL 变更需要 PostgreSQL 路径；PTY/ACP 生命周期需要真实进程和真实 Agent 场景；发行与安装需要 Linux/macOS × amd64/arm64 的实际产物及适用平台验收。

本次评审此前已完成基线 Go 测试、Go vet、Web 检查与构建，并用临时测试复现三项正确性缺陷。PostgreSQL、真实 Agent 和完整发行平台矩阵未在本次环境中完成验收。本文整理没有重新运行测试，也不把基线通过当作未来实现已验证。

## 8. 保留的成本与边界

- 5 秒是 Dune 对可观察失效的传播合同，不补齐宿主身份源缺失的注销能力。
- 内容摘要增加 I/O；大目标的 conditional 校验仍会串行占用文件写锁。
- 外部文件写入与跨块读取不具备文件系统快照保证；搜索结果也可能在展示后失效。
- 有序目录分页采用有界内存但仍逐页扫描；需要更低扫描延迟时再独立评估有状态方案。
- 搜索预算会截断大查询和长行；界面必须诚实展示范围与不完整原因。
- 主机休眠期间无法执行终止；主动脱离进程组的进程不在本轮强终止保证内。
- 升级后旧程序被清理，没有自动回退承诺；保存 PTY 不代表所有 ACP/Agent 进程无感存活。

以上成本已通过明确合同控制，优先保留可理解的实现，不为了掩盖限制再引入通用策略框架、全局文件事务、搜索索引平台或跨版本状态兼容层。
